# Swarm 파라미터 설명

**알고리즘**: 2D irregular strip packing — SPARROW (Jaguars-Guided Local Search)  
**논문**: Algorithm 1~13, [arXiv:2509.13329](https://doi.org/10.48550/arXiv.2509.13329)  
**원본 Repo 주소**: https://github.com/JeroenGar/sparrow
---

# 1. Swarm Config

>## RngSeed    
>난수 생성기 시드 값입니다. 동일한 시드와 입력 데이터에 대해 항상 동일한 결과를 재현할 수 있습니다.</br>
0을 입력하면 무작위 시드(현재 시간 기반)가 사용되어 실행할 때마다 다른 결과가 나옵니다.</br>
재현 가능한 결과가 필요하면 0이 아닌 값을 설정하십시오.

>## PolySimpl (PolySimplTolerance)
>다각형 단순화 허용 오차입니다. </br>
값이 클수록 아이템의 꼭짓점이 더 많이 줄어들어 계산 속도가 빨라지지만, 
단순화된 도형은 원본보다 약간 부풀려져(inflation) 실제보다 더 큰 면적으로 인식됩니다. </br>
값이 작을수록 원본에 가깝지만 충돌 감지 비용이 증가합니다. 0.001(0.1%)이 권장 기본값이며, 
고정밀 배치가 필요하면 더 작은 값을, 고속 처리가 필요하면 더 큰 값을 사용하십시오. </br>
비활성화하려면 체크 해제하십시오.

>## MinSep (MinItemSeparation)
>아이템 간 최소 이격 거리(mm)입니다.
이 값을 설정하면 모든 아이템이 서로 및 컨테이너 경계로부터 지정된 거리만큼 떨어져 배치됩니다. </br>
커터 보정(cutter compensation), CNC 가공 여유, 또는 열 수축 마진이 필요한 경우에 유용합니다. </br>
0으로 설정하면 아이템 간 간격 없이 밀착 배치됩니다. </br>
비활성화하려면 체크 해제하십시오.

>## NarrowCC Dist (NarrowConcavityCutoffDist)
>좁은 오목부(Narrow Concavity) 판정을 위한 최대 거리 기준입니다. 
아이템 도형의 오목한 부분 중 너비가 이 값보다 좁으면 '좁은 오목부'로 간주되어 닫힘(채움) 처리됩니다. 
</br>이 처리는 오목부에 다른 작은 아이템이 들어갈 수 없을 정도로 좁은 경우에만 적용되어 불필요한 충돌 감지 연산을 줄여줍니다. </br>
단위는 아이템의 전체 경계 상자(bounding box) 대각선 길이에 대한 비율입니다. 예: 0.01 = 전체 크기의 1%. </br>
비활성화하려면 체크 해제하십시오.

>## NarrowCC Area (NarrowConcavityCutoffArea)
>좁은 오목부(Narrow Concavity) 판정을 위한 최대 면적 기준입니다. </br>
아이템 도형의 오목한 부분 중 면적이 이 값보다 작으면 '좁은 오목부'로 간주되어 닫힘(채움) 처리됩니다.
</br>
거리 기준(NarrowConcavityCutoffDist)과 함께 AND 조건으로 적용되어, 폭이 좁으면서 면적도 작은 오목부만 필터링합니다. </br>
단위는 아이템 전체 면적에 대한 비율입니다. 예: 0.01 = 전체 면적의 1%. </br>
비활성화하려면 체크 해제하십시오.

>## 겹침 초과 배치 (OriginalOverlapPolicy)
>겹침 허용(PieceOverlapMm)을 켰을 때, **원래 외곽선**끼리의 겹침이 허용값을 넘는 배치를 어떻게 볼지 정합니다. </br>
탐색은 조각을 허용값의 절반만큼 줄인 도형으로 하고, 결과를 원래 외곽선으로 다시 검증합니다.
뾰족한 꼭짓점은 줄이기에서 변보다 더 깎이므로, 줄인 도형끼리는 겹치지 않아도 원래 외곽선은 허용값보다 깊이 겹칠 수 있습니다.
이때 네이티브 로그 `[ORIGINAL:VALIDATE] original overlap exceeds configured piece_overlap_mm: items A/B` 가 남습니다. </br>
• 실현 불가능 (기본): 그런 배치를 버리고 직전에 인증된 배치를 유지합니다. 구성·탐색 중에도 원래 외곽선 기준으로 초과를 막고 보정합니다. </br>
• 실현 가능: 원래 외곽선 검증을 끄고 그대로 채택합니다. 겹침은 줄인 도형으로만 판정하므로, 뾰족한 꼭짓점이 허용값보다 깊이 파고들 수 있습니다. 원단 경계 검사(원단 밖 허용)는 그대로입니다. </br>
겹침 허용이 0이면 효과가 없습니다. C ABI v19 `COriginalOverlapConfig.excess_policy`(0 = 실현 불가능, 1 = 실현 가능)에 해당합니다.

>## 그룹 배치 방식 (PlaceGroupMode)
>V2 입력의 `place_groups`(패턴 그룹)를 엔진에 넘기는 방식입니다. </br>
• 다중 폴리곤 아이템 (기본): 그룹마다 멤버의 원래 외곽선을 `placed_hint` 자세대로 합친 아이템 하나를 만들어 보통 조각처럼 배치합니다. 엔진은 멤버 폴리곤마다 충돌을 검사하므로 멤버 사이 틈에는 다른 조각이 들어갈 수 있고, 멤버의 상대 자세는 정의상 정확합니다. 결과는 멤버별 자세로 풀어 돌려주므로 출력 형식은 그대로입니다. </br>
• 강체 이동: 멤버를 별도 조각으로 두고 상대 좌표로 함께 옮깁니다(1.0.2 까지의 방식). 비교·회귀 확인용입니다. </br>
C ABI v20 `CPlaceGroupConfig.mode`(0 = 다중 폴리곤 아이템, 1 = 강체 이동)에 해당합니다. 0 으로 초기화한 호출자는 기본값을 받습니다. </br>
멤버 사이 겹침 허용(PieceOverlapMm)은 두 방식 모두 멤버마다 적용되고, 그룹의 허용 회전은 멤버 허용 회전의 교집합입니다.

# 2. Exploration Config — 탐색 단계 설정

>## ShrinkStep
>탐색 단계에서 스트립 폭을 줄이는 비율입니다. 
각 반복마다 현재 스트립 폭에 (1 - ShrinkStep)을 곱해 점진적으로 좁혀갑니다. </br>
값이 클수록 더 빠르게 폭을 줄이지만, 너무 크면 실현 가능한 배치를 놓칠 수 있습니다. </br>
값이 작을수록 더 촘촘하게 탐색하지만 시간이 더 오래 걸립니다. </br>
기본값 0.001(0.1%씩 축소)은 대부분의 경우에 적합합니다. </br>
복잡한 도형이 많으면 0.0005 정도로 낮추고, 단순 도형 위주면 0.002 이상으로 높여도 됩니다.

>## TimeLimit(s)
>탐색 단계의 최대 실행 시간(초)입니다. </br>
시간이 초과되면 그 시점까지 찾은 최적 솔루션으로 압축 단계로 넘어갑니다. </br>
아이템 개수가 많거나 도형이 복잡할수록 더 긴 시간이 필요합니다. </br>
50개 이하 소규모 배치는 60-120초, 100개 이상 대규모 배치는 300-540초가 권장됩니다. </br>
너무 짧게 설정하면 충분히 최적화되지 않은 상태에서 종료됩니다.

>## MaxFail (MaxConseqFailedAttempts)
>연속 실패 허용 횟수입니다. </br>
탐색 단계에서 이 횟수만큼 연속으로 스트립 폭 축소에 실패(실현 가능한 배치를 찾지 못함)하면 탐색을 조기 종료합니다. </br>
값이 작을수록 빠르게 포기하지만 최적해를 찾을 기회를 놓칠 수 있고, 값이 클수록 끈질기게 탐색하지만 시간이 더 소요됩니다. </br>
0-5는 공격적 조기 종료, 10-20은 보수적 탐색에 적합합니다. </br>
비활성화하면(None) 시간 제한이 끝날 때까지 계속 탐색합니다.

>## PoolStdDev (SolutionPoolStdDev)
>솔루션 풀(Solution Pool) 분포의 표준편차입니다. 
탐색 과정에서 여러 솔루션 후보를 유지하고 변형할 때, 이 값이 클수록 더 다양한(무작위적인) 변형을 시도하여 지역 최적해(local optima) 탈출에 유리합니다. </br>
값이 작을수록 현재 최적해 근처에서 집중적으로 탐색합니다. </br>
0.25(기본값)는 균형 잡힌 값이며, 지역 최적해에 갇히는 현상이 보이면 0.3~0.5로 높여보십시오.

>## LargeItem% (LargeItemCutoffPercentile)
>대형 아이템 판정을 위한 볼록 껍질(Convex Hull) 면적 기준 백분위입니다. </br>
전체 아이템 중 볼록 껍질 면적이 상위 N%에 해당하는 아이템을 '대형 아이템'으로 분류합니다. </br>
대형 아이템은 탐색 중 클러스터 교란(cluster disruption) 전략에서 우선적으로 이동 대상이 됩니다. </br>
0.75(기본값)는 상위 25% 아이템을 대형으로 분류합니다. </br>
작은 아이템이 많은 데이터셋에서는 0.8-0.9로 높이고, 큰 아이템 위주면 0.5-0.6으로 낮추십시오.

# 3. Exploration Separator Config — 탐색 단계 중첩(충돌) 분리기 설정

>## IterNoImprv (IterNoImprvLimit)
>탐색 단계의 중첩 분리기(Separator)가 개선 없이 허용하는 최대 반복 횟수입니다. </br>
충돌 해소를 반복하는 동안 이 횟수만큼 연속으로 스트립 폭이 개선되지 않으면 분리기가 중단됩니다. </br>
값이 클수록 더 많은 충돌 해소 기회를 제공하지만 시간이 증가합니다. </br>
탐색 단계는 넓은 범위를 탐색하므로 압축 단계보다 큰 값(200~500)이 적합합니다.

>## StrikeLimit (StrikeLimit)
>탐색 단계의 중첩 분리기에서 허용하는 최대 연속 실패(스트라이크) 횟수입니다. </br>
충돌 해소 시도가 이 횟수만큼 연속으로 실패하면 현재 솔루션을 포기하고 새로운 시도를 시작합니다. </br>
값이 작을수록 빠르게 다른 접근을 시도하고, 값이 클수록 현재 접근을 더 오래 밀어붙입니다. </br>
탐색 단계는 다양한 시도가 중요하므로 3-5 정도의 작은 값이 일반적으로 적합합니다.

>## NumWorkers
>탐색 단계의 중첩 분리기에서 사용할 병렬 워커(Worker) 수입니다. </br>
각 워커는 독립적으로 충돌하는 아이템을 이동시키며, CPU 코어 수만큼 설정하면 최대 병렬 성능을 얻을 수 있습니다. </br>
너무 많은 워커는 컨텍스트 스위칭 오버헤드를 유발할 수 있으므로, 일반적으로 물리 코어 수의 50-75%가 적절합니다. 예: 8코어 CPU → 4-6개.

>## ContainerSmpl (NumContainerSamples)
>탐색 단계에서 충돌 아이템 이동 시 컨테이너 전체 영역에서 생성하는 랜덤 샘플 수입니다. </br>
각 충돌 아이템을 새로운 위치로 이동시킬 때 이 개수만큼 컨테이너 내 무작위 위치를 시도합니다. </br>
값이 클수록 더 좋은 위치를 찾을 확률이 높지만 시간이 증가합니다. </br>
넓은 스트립 폭의 탐색 단계에서는 50~100이 적절하며, 아이템이 많을수록 더 많은 샘플이 필요합니다.

>## FocussedSmpl (NumFocussedSamples)
>탐색 단계에서 충돌 아이템 이동 시 현재 위치 근처(집중 영역)에서 생성하는 랜덤 샘플 수입니다. </br>
컨테이너 전체 샘플과 달리, 현재 위치 주변의 좁은 영역에서 국소적으로 더 나은 위치를 찾습니다. </br>
값이 클수록 미세 조정에 유리하지만 시간이 증가합니다. </br>
탐색 단계는 넓은 범위 탐색이 주목적이므로 25~50 정도의 적당한 값이 권장됩니다.

>## CoordDescents (NumCoordDescents)
>탐색 단계에서 각 샘플 배치 후 실행할 좌표 하강(Coordinate Descent) 횟수입니다. </br>
좌표 하강은 랜덤 샘플로 찾은 위치를 X축, Y축, 회전 각도별로 미세하게 조정하여 더 나은 위치로 수렴시킵니다. </br>
값이 클수록 각 샘플이 더 정밀하게 최적화되지만 시간이 증가합니다. </br>
탐색 단계에서는 3~5회가 적절하며, 이 값 이상은 수확 체감(diminishing returns)이 큽니다.

# 4. Compression Config — 압축 단계 설정

>## ShrinkMin (ShrinkRangeMin)
>압축 단계에서 사용할 최소 축소 비율입니다. 
탐색 단계의 마지막 스트립 폭에 이 비율을 곱한 값이 압축 단계의 첫 번째 목표 폭이 됩니다. </br>
값이 클수록 공격적으로 압축을 시도하지만 실현 불가능한 목표일 가능성도 높습니다. </br>
일반적으로 탐색 단계의 ShrinkStep보다 작은 값을 사용합니다(예: 0.001~0.0005). </br>
ShrinkRangeMax보다 커야 합니다.

>## ShrinkMax (ShrinkRangeMax)
>압축 단계에서 사용할 최대 축소 비율입니다. </br>
압축이 진행될수록 스트립 폭이 점점 좁아지고, 최종적으로 이 비율까지 도달하면 압축을 중단합니다. </br>
값이 작을수록 더 정밀하게 미세 압축을 시도합니다. </br>
ShrinkRangeMin보다 작아야 하며, 일반적으로 0.00001~0.0001 범위의 매우 작은 값을 사용합니다. </br>
너무 작으면 수렴에 시간이 오래 걸리므로 주의하십시오.

>## TimeLimit(s)
>압축 단계의 최대 실행 시간(초)입니다. </br>
시간이 초과되면 그 시점까지 찾은 최적 솔루션이 최종 결과가 됩니다. </br>
압축 단계는 탐색 단계보다 미세한 조정을 하므로 상대적으로 짧은 시간(탐색 시간의 10~20%)으로 충분합니다. 
</br>30~60초가 일반적이며, 고정밀 배치가 필요하면 120초까지 늘릴 수 있습니다.

>## Decay (ShrinkDecay)
>압축 단계의 축소 감쇠(Shrink Decay) 전략입니다.<br>
• TimeBased: 시간 경과에 따라 축소 비율이 선형적으로 감소합니다. </br>
초반에는 공격적으로, 후반에는 보수적으로 압축합니다. </br>
일반적인 상황에 가장 적합한 기본 전략입니다.<br>
• FailureBased: 압축 시도가 실패할 때마다 축소 비율에 지정된 감쇠 비율(ShrinkDecayRatio)을 곱해 점진적으로 줄입니다. </br>
연속 실패가 많은 데이터셋에 효과적이며, 실패가 적으면 공격적인 압축을 유지합니다.

>## DecayRatio (ShrinkDecayRatio)
>FailureBased 축소 감쇠 전략 사용 시, 압축 실패마다 현재 축소 비율에 곱해지는 감쇠 비율입니다. </br>
0.9(기본값)는 실패할 때마다 축소 폭이 10%씩 줄어듭니다.<br>
1.0에 가까울수록 실패 후에도 공격적인 압축을 유지하고, 작을수록 빠르게 보수적으로 전환합니다. </br>
TimeBased 전략에서는 이 값이 무시됩니다.

# 5. Compression Separator Config — 압축 단계 중첩(충돌) 분리기 설정

>## IterNoImprv (IterNoImprvLimit)
>압축 단계의 중첩 분리기(Separator)가 개선 없이 허용하는 최대 반복 횟수입니다. </br>
충돌 해소를 반복하는 동안 이 횟수만큼 연속으로 스트립 폭이 개선되지 않으면 분리기가 중단됩니다. </br>
압축 단계는 미세 조정이 목적이므로 탐색 단계보다 작은 값(100~200)이 적합하며, 너무 크면 미세한 개선에 과도한 시간을 소비할 수 있습니다.

>## StrikeLimit
>압축 단계의 중첩 분리기에서 허용하는 최대 연속 실패(스트라이크) 횟수입니다. </br>
충돌 해소 시도가 이 횟수만큼 연속으로 실패하면 현재 솔루션을 포기하고 새로운 시도를 시작합니다. </br>
압축 단계는 탐색 단계보다 좁은 폭에서 작업하므로 실패 확률이 더 높아, 좀 더 큰 스트라이크 한계(5~10)가 적합합니다.

>## NumWorkers
>압축 단계의 중첩 분리기에서 사용할 병렬 워커(Worker) 수입니다. </br>
각 워커는 독립적으로 충돌 아이템을 이동시킵니다. </br>
CPU 코어 수만큼 설정하면 최대 병렬 성능을 얻을 수 있으며, 일반적으로 탐색 단계와 동일한 값(물리 코어 수의 50~75%)을 사용하는 것이 좋습니다.

>## ContainerSmpl (NumContainerSamples)
>압축 단계에서 충돌 아이템 이동 시 컨테이너 전체 영역에서 생성하는 랜덤 샘플 수입니다. </br>
압축 단계는 이미 좁은 스트립 폭에서 작업하므로 탐색 단계보다 더 많은 샘플이 도움이 될 수 있습니다. </br>
50~100이 일반적인 범위이며, 아이템 밀도가 높을수록 더 많은 샘플이 필요합니다.

>## FocussedSmpl (NumFocussedSamples)
>압축 단계에서 충돌 아이템 이동 시 현재 위치 근처(집중 영역)에서 생성하는 랜덤 샘플 수입니다. </br>
압축 단계는 미세 조정이 핵심이므로, 집중 샘플을 충분히 확보하는 것이 중요합니다. </br>
25~50이 적절하며, 아이템이 조밀하게 배치될수록 더 많은 집중 샘플이 미세 조정에 도움이 됩니다.

>## CoordDescents (NumCoordDescents)
>압축 단계에서 각 샘플 배치 후 실행할 좌표 하강(Coordinate Descent) 횟수입니다. </br>
좌표 하강은 샘플 위치를 X축, Y축, 회전 각도별로 미세하게 조정합니다. </br>
압축 단계는 미세 조정이 핵심이므로 탐색 단계와 동일하거나 약간 더 많은 3~5회가 권장됩니다. </br>
너무 많은 횟수는 시간 대비 개선 효과가 미미합니다.


# 6. Polish Config — 후처리 단계 설정

압축 단계가 끝난 **실현 가능한(feasible) 해**에 대해 결정론적인 정리 패스를 적용하는 단계입니다.
탐색/압축은 스트립 폭을 통째로 줄이고 다시 분리를 돌리는 확률적 방식이라, 겹치지 않는 아이템은
애초에 이동 대상이 아닙니다. 그래서 feasible 해에 남은 자잘한 틈은 그대로 방치되는데, 이 단계가 그 틈을 회수합니다.

세 패스가 순서대로, NumRounds회 반복됩니다.
모든 패스는 이동을 반영하기 전에 충돌을 검증하므로 **결과가 압축 단계보다 나빠지지 않으며**,
고정(Freeze)된 아이템은 어느 패스에서도 이동하지 않습니다.

>## Enabled
>후처리 단계 사용 여부입니다. </br>
끄면 압축 단계의 결과가 그대로 최종 결과가 됩니다.

>## TimeLimit(s)
>후처리 단계 전체의 최대 실행 시간(초)입니다. </br>
시간이 초과되면 그 시점까지 확보한 최적 솔루션이 최종 결과가 됩니다. </br>
세 패스 모두 수십~수백 ms 수준으로 끝나므로 10~30초면 충분합니다.

>## NumRounds
>slide → hole fill → lp 사이클을 몇 번 반복할지입니다. </br>
LP가 배치를 조이면 새로운 틈과 포켓이 생기므로, 다시 슬라이딩/포켓 채우기를 돌리면 추가 개선이 나옵니다. </br>
더 이상 바뀌는 것이 없으면 지정 횟수 전에 자동으로 종료합니다.

## 6-1. Slide — 결정론적 좌측 슬라이딩

각 도형을 **접촉할 때까지 왼쪽으로**(옵션에 따라 아래쪽으로도) 밀어 넣습니다.
이동 거리는 충돌 검사를 전방 스캔 + 이분탐색으로 구하므로, 반영되는 거리는 항상 충돌 없음이 검증된 값입니다.

>## SlideEnabled
>좌측 슬라이딩 패스 사용 여부입니다.

>## SlideNumPasses
>한 라운드 안에서 슬라이딩을 반복할 횟수입니다. </br>
앞의 아이템이 왼쪽으로 빠지면 뒤따르는 아이템이 그 자리를 이어받을 수 있어 반복이 효과가 있습니다. </br>
더 이상 움직이지 않으면 지정 횟수 전에 자동으로 종료합니다.

>## SlideDown
>좌측 슬라이딩 후 하단 방향 슬라이딩도 수행할지입니다. </br>
아래로 모아두면 위쪽에 연속된 여유가 생겨 뒤이어 실행되는 LP가 더 많이 줄일 수 있습니다.

>## SlideSafetyRatio
>접촉 직전에 남겨둘 안전 간격입니다. 아이템의 가장 짧은 변 길이에 대한 비율입니다. </br>
0이면 닿을 때까지 밀어넣습니다. 커터 보정이 필요하면 MinItemSeparation을 쓰는 편이 정확합니다.

## 6-2. Hole Fill — 타깃형 빈 포켓 채우기

레이아웃을 균일 격자로 래스터화해 **아이템들에 둘러싸인 닫힌 빈 포켓을 명시적으로 찾아내고**,
스트립 우측의 작은 아이템부터 그 안으로 재배치를 시도합니다.
포켓의 빈 셀을 앵커로 삼아 왼쪽부터 훑으며, 충돌이 없고 아이템의 우측 끝이 실제로 왼쪽으로 이동할 때만 반영합니다.

>## HoleFillEnabled
>빈 포켓 채우기 패스 사용 여부입니다.

>## HoleFillCellSizeRatio
>점유 격자의 셀 크기입니다. 가장 작은 아이템의 최소 변 길이에 대한 비율입니다. </br>
값이 작을수록 포켓 모양을 정밀하게 잡아내지만 격자 구성 비용이 제곱으로 늘어납니다. </br>
셀 개수가 내부 상한을 넘으면 셀 크기가 자동으로 커집니다.

>## HoleFillMaxCandidates
>재배치를 시도할 아이템 수 상한입니다. 면적이 작은 것부터 선택합니다. </br>
작은 조각일수록 포켓에 들어갈 확률이 높습니다.

>## HoleFillCandidateBand
>재배치 후보를 고를 구간입니다. 스트립 우측 몇 %에 걸쳐 있는 아이템을 대상으로 할지 정합니다(0.0~1.0). </br>
우측 끝에 있는 아이템을 왼쪽 포켓으로 옮겨야 스트립 폭이 줄어듭니다. </br>
1.0으로 두면 모든 아이템을 검토하지만 시간만 더 쓰고 이득은 거의 없습니다.

>## HoleFillNumSamples
>포켓 하나당 평가할 배치 후보 수입니다. </br>
포켓의 빈 셀이 이보다 많으면 균등 간격으로 솎아내어 사용합니다.

## 6-3. LP Compaction — 선형계획 기반 압축

아이템별 평행이동 (dx, dy)과 스트립 폭 W를 변수로 하는 선형계획을 세워 W를 최소화합니다.
비겹침 조건은 접촉 중인 쌍의 **정점-모서리 분리 제약**으로 선형화합니다.
비볼록 도형이라 선형화가 완전하지 않을 수 있으므로, **해를 적용한 뒤 반드시 충돌을 전수 검증하고
실패하면 이동량을 절반씩 줄여 재시도**합니다. 따라서 어떤 경우에도 겹침이 생기지 않습니다.

>## LpEnabled
>LP 압축 패스 사용 여부입니다. 세 패스 중 폭 감소 기여도가 가장 큰 패스입니다.

>## LpNumIterations
>LP 수립 → 적용 반복 횟수 상한입니다. </br>
더 이상 줄일 수 없으면 상한 전에 자동으로 수렴하므로, 넓게 잡아도 시간 낭비가 크지 않습니다.

>## LpTrustRegionRatio
>신뢰 영역(한 번에 허용하는 이동량)의 **기본(가장 촘촘한) 단계** 크기입니다. 스트립 폭에 대한 비율입니다. </br>
작은 스텝은 선형화가 정확해 더 촘촘하게 밀어 넣지만 얕은 지역해에 갇히고,
큰 스텝은 배치를 크게 재배열하는 대신 근사 오차가 커집니다. </br>
그래서 이 값에서 시작해 개선이 막힐 때마다 2배씩 키우고, 한 번이라도 개선되면 다시 기본 단계로 돌아갑니다. </br>
0.005(0.5%)가 권장 기본값입니다.

>## LpLeftPullWeight
>모든 아이템을 왼쪽으로 당기는 목적항의 가중치입니다(폭 W의 계수 1.0 대비). </br>
폭을 결정하지 않는 아이템도 왼쪽으로 모아 다음 반복에서 줄일 여지를 만듭니다. </br>
너무 크면 폭 최소화 목적을 흔들어 오히려 수렴이 느려집니다.
