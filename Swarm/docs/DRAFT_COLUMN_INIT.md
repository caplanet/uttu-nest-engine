# Column Draft Init

## 목적과 사용

사용자가 확인한 진행 방식인 **왼쪽 아래 → 위쪽 열 채움 → 열의 틈 재탐색 → 다음 열의 아래쪽**을 별도 초기 생성기로 구현했다.

WPF의 LBF 설정 옆 **`Draft Init — 아래에서 위로 열 채움`**을 켠다. 기본은 꺼짐이다.
새 legacy strip 입력에서는 LBF를 먼저 실행하지 않고 Draft로 직접 시작한다.
기존 실험 `refplace` 옵션과 함께 켜면 Column Draft가 우선하며, NFP-LBF 보조 시드가 결과를 교체하지 않는다.
Use Hints/입력 solution/고정 배치를 지정하면 기존 시드 경로를 우선한다. 다른 조각까지 임의로 재배치하지 않는다.
영역 및 rigid place-group 전용 엔진은 이번 변경 대상이 아니다.

Rust 설정: `config.refplace.enabled = true; config.refplace.column_draft = true;`
C# 설정: `RefPlace.Enabled = true; RefPlace.ColumnDraft = true;`
C ABI: `refplace.enabled=1`, `refplace._reserved0=1`. 기존 예약 슬롯을 사용해 크기와 오프셋은 유지한다.
0은 종전 실험 엔진이며 다른 예약 값도 Column Draft를 활성화하지 않는다.

허용 회전은 전부 `[0]`이다. 배치 이력이나 부착 대상을 담고 있지 않다.
따라서 **원 엔진의 실행 순서 복원이 아니라, 명시한 진행 방식을 구현한 실험 생성기**다.
특정 ID, 참조 좌표, 스타일/사이즈 이름을 알고리즘에 넣지 않았다.
코어 생성기는 `SPInstance`만 받으며 `placed_hint`에 접근할 수 없다. 벤치마크도 힌트를 제거한다.

### 열의 생성

1. bbox 대각선 × `(1 + 5 × 왼쪽 오목도 + 2 × 아래 오목도)` 내림차순으로 열 루트 후보를 정렬한다. 동률은 ID/사본 순으로 고정한다. 방향별 오목도는 기존 hull-pocket 분석의 면적 비율을 쓴다.
2. 가장 앞 조각을 열의 루트로 삼고, 들어갈 수 있는 허용 회전 중 폭이 작은 자세를 선택한다.
3. 첫 열은 원단 좌하단에서 시작한다. 다음 열의 루트는 앞 열의 범위 안까지 접촉 탐색해 윤곽에 맞물릴 수 있다.
4. 다음 조각의 **왼쪽 끝**이 `column_left .. column_left + root_width / 2`인 접촉을 현재 열에서 찾는다. 조각의 오른쪽 끝을 루트 폭으로 제한하지 않는다. 배치될 때마다 열 윤곽이 넓어질 수 있다. 이 범위는 재구현의 유한 탐색 규칙이며 참조 엔진에서 복원된 상수가 아니다.
5. 현재 진행 높이 위쪽에 들어갈 수 있는 남은 조각을 높이로 거른다. **작업 목록의 순서대로 조각 하나씩** 평가한다. 해당 조각의 허용 회전을 순회하고, 배치 가능한 최고 점수 위치를 찾은 첫 회전에서 확정한다. 여러 조각의 점수를 비교하던 8개 lookahead는 사용하지 않는다. `ColumnDraftConfig.shortlist` 필드는 Rust 호출부 호환용으로 남아 있지만 선택에 사용하지 않는다.
6. 배치할 수 없는 조각은 pending에 남겨 다음 조각을 확인한다. 후보가 없으면 진행 높이를 아래로 되돌려 같은 순서로 틈을 확인한다. 틈 채움에서도 후보가 없으면 열을 마감하며 보류 조각은 다음 열에서 재시도한다.

제한된 부착 대상과 위치 창으로 인해 **열 마감은 전역적으로 더 들어갈 조각이 없다는 증명이 아니다.**
순차 배치와 최초 성공 회전 규칙도 최적 밀도를 보장하지 않는다.

### 후보와 부착

- 128mm 공간 인덱스로 탐색 범위에 접하는 기배치 윤곽을 조회한다. 왼쪽 아래에서 가까운 최대 10개와 명시적 체인의 추가 2개를 부착 후보로 유지한다. 최근에 놓은 조각만 보는 대신, 앞서 놓였어도 현재 빈 공간에 접하는 조각을 다시 사용할 수 있다.
- 다음 열의 루트는 직전 열 체인과 해당 위치의 윤곽을 사용한다. 후보 생성에 전체 기배치 조각을 매번 넣어 NFP 합집합을 만들지 않는다.
- NFP의 성분/홀 경계는 서로 연결하지 않고 그대로 유지한다.
- 경계의 전체 꼭짓점 사건, NFP와 원단/열 경계의 교차점, NFP와 NFP의 교차점으로 접촉 후보를 만든다. 정점 부분 샘플링으로 대체하지 않는다.
- bbox로 교차 가능한 접촉쌍을 걸러 거리² 순으로 처리한다.
- 접촉점의 네 방향에 0.02mm 보조 후보를 만들고, 정확한 접촉점도 유지한다. 이는 full-height 도형의 경계 접촉을 허용하기 위해서다.
- NFP 내부 판정은 빠른 후보 제외에만 사용한다. 최종 허용은 사용자의 공차가 반영된 충돌 도형을 실제 f32 변환한 결과로 판정한다.
- 허용된 후보는 왼쪽/아래로 각각 최대 5mm 범위에서 이분 탐색으로 접촉을 보정한다. 이는 단순화로 늘어난 틈을 줄이는 탐색 범위이며 **추가 겹침 허용값이 아니다.** 모든 이동은 충돌 검사를 통과해야 한다.
- 확정한 후보의 부착 대상은 placement sequence의 인덱스로 기록한다. 같은 `item_id`가 여러 개라도 모호하지 않다.
- 부착 대상이 없는 일반 조각은 보류한다. 열의 첫 조각은 별도의 루트 생성 단계에서 독립 배치해 보류 체인이 영원히 시작하지 못하는 것을 방지한다.
- NFP 쌍은 고정/이동 ID와 양쪽 회전을 모두 포함한 정렬 배열로 준비하고, 배치 단계에서 이진탐색으로 조회한다. 실패/빈 경계는 사용할 수 있는 NFP로 취급하지 않는다. 다른 부착 후보가 있으면 그 경계는 계속 사용할 수 있다.
- 현 NFP 커널에는 정점 수에 넣는 숫자형 `FULL_OVERLAP_MARK`가 없다. 대신 NFP 내부가 **현재 허용 이동 창 전체**를 덮는 것이 확인되면 `Held`로 분류한다. 네 모서리의 내부 여부만으로 단정하지 않고, 창에 닿거나 들어오는 변이 없는지도 확인해 오목부/홀을 놓치지 않는다. 이 상태는 창에 의존하므로 재사용 NFP 캐시에 전역 표식으로 저장하지 않는다.
- 조각 1회의 시도에서 회전들을 합해 위치 평가를 최대 **10,000회**로 제한한다. 후보 점수 계산과 접촉 보정의 새 위치도 같은 상한을 사용한다. 경계 사건 생성도 최대 10,000개로 제한하고 시간 만료를 확인한다. 한도 안 후보를 점수순 정렬했으므로, 정밀 검사를 처음 통과한 위치가 그 후보 묶음의 최고 점수다. 확정/최종 검증은 탐색 횟수에 넣지 않는다.

### 판정과 점수

실제 다각형 면적을 0.01mm 그리드의 i64 면적으로 계산한다. 곱셈 및 합계 중간값은 i128이다.
2026-09-09 사용자 확인에 따라 다음 **면적 산식 자체**를 적용한다. 기존 가중 효율 차이로 바꾸지 않는다. 높은 점수가 우선이다:

```text
value       = 배치면적 / (배치 개수 × 기준면적)
avg_s       = 배치면적 / 스트립수
최종 점수   = v_max - 8 × max_s(avg_s)

d = (1 - value / v_max) × 100
d <= 0.2         : w = 0
0.2 < d <= 0.5   : w = 1 - 0.5 × d
0.5 < d <= 1.0   : w = 1
d > 1.0          : w = 0.5
```

변수 연결은 다음과 같다.

- 배치면적: 이미 확정한 조각들과 후보 조각의 `shape_cd` 실제 다각형 면적 합(mm²). bbox 면적이 아니다. 경계에 걸친 후보는 직사각형으로 다각형을 잘라 면적을 계산한다. 전부 안에 있으면 준비한 자세의 면적을 재사용한다. 원본 면적이나 중첩 영역의 합집합 면적은 아니다.
- 개수: 확정 조각 수 + 현재 후보 1개. 사본도 개별 조각으로 센다.
- 기준면적: 후보 배치 후 CD 사용 길이 × CD 원단 높이. 내부 계산용으로 넓혀 둔 전체 완료 공간의 면적을 분모로 사용하지 않는다.
- 표면/스트립수: 현재 단일 원단 `SPInstance`를 표면 1개, 스트립수 1로 해석했다. 열을 별도 원단으로 세지 않는다. 이는 원단/열 구분에 대한 추가 답변이 없는 상태에서 현재 API에 맞춘 해석이다.
- `v_max`: 해당 회전의 한도 내 위치 제안 묶음에서 `value`의 최댓값. NFP/정밀 검사로 거부될 제안도 이 공통 기준값 계산에 포함된다. 선택 후 접촉 보정으로 더 높은 값이 나오면 갱신한다.
- 동일 점수면 `value`가 높은 쪽, 이어서 왼쪽·아래쪽 위치를 택한다. 같은 조각의 면적이 유지되는 경우에는 `value` 비교가 사용 길이 비교에 해당한다.

**`avg_s`는 mm²이며 점유율이 아니다.** 따라서 이 식을 "가장 덜 찬 표면에 대한 정규화된 벌점"이라고 설명하면 안 된다. 원단 안에서 같은 조각을 옮기는 후보끼리는 배치면적과 `avg_s`가 같아질 수 있고, 이때 실제 위치 선택은 동점 기준에 의존한다.

4구간 가중치는 그대로 계산해 배치 리포트 `scoring.weight`에 남긴다. 사용자가 확정한 최종 산식에는 `w`를 곱하는 항이 없으므로 임의로 면적에 곱하거나 `w=0`인 최고 후보를 버리지 않는다. `scoring`에 분자·분모·개수·평균·기준값·최종 점수를 함께 기록해 재계산할 수 있다. 루트/시간 만료 완료 배치처럼 점수 선택을 거치지 않은 배치에는 이 기록이 없다.

`refplace/column_score.rs`가 현재 Draft의 면적 산식이다. 기존 `refplace/score.rs`의 다중 표면 가중평균은 종전 실험 엔진에 유지하며, Draft는 그 모듈에서 `shortfall`과 4구간 `weight` 함수만 공유한다.

확정 전에는 공간 인덱스로 bbox 충돌 가능성이 있는 **모든 기배치 조각**을 찾아 양방향 다각형 충돌을 검사한다.
변이 같은 방향으로 일직선상에서 겹치는 경우도 추가 검사한다. 기존 교차/POI 함수만 쓰면 얕게 포개진 정렬 직사각형을 놓칠 수 있기 때문이다. 반대 방향으로 공유하는 변의 접촉은 허용한다.
부착 대상 제한은 후보 생성의 제한이지 충돌 검사 생략이 아니다.
완료 시 기존 `solution_validation_error`로 수량, 허용 회전, 원단 경계, 겹침을 다시 인증한다.
겹침 공차가 활성화된 경우 후보 검사와 접촉 보정에도 최종 인증과 동일한 원본 겹침 판정을 적용한다. 이미 배치된 원본 경로는 캐시하며, 공간 인덱스는 CD와 원본 bbox를 함께 포함한다. 축소 도형만 통과한 후보가 마지막에 원본 검사로 거부되던 문제를 막는다. 이 검사에서는 새로운 겹침 한도를 추가하지 않는다.
실패한 해는 반환하지 않는다. Init 호출부는 사유를 로그에 남기고 기존 LBF로 폴백한다.

### 겹침 공차

WPF의 기존 **겹침 허용(mm)** 값을 그대로 사용한다. 양수이면 네이티브 import에서 각 조각의 `shape_cd`를 공차의 절반씩 축소한다. NFP 제안, 접촉 보정, 배치 인증이 모두 이 도형을 기준으로 한다. Draft가 별도의 공차를 추가하거나 UI 값을 자동으로 올리지 않는다.
원단은 같은 양만큼 안쪽으로 보정한다. 다만 뾰족한 꼭짓점은 균일 오프셋보다 축 방향으로 더 크게 후퇴하므로 이 보정만으로 원본 경계 준수를 보장할 수 없다. Draft는 `shape_orig`에 전처리 변환과 허용 회전을 적용한 원본 bbox도 준비하고, 후보 범위·접촉 보정·시간 소진 완료·최종 원단 길이를 원본 윤곽으로 함께 제한한다. 0이면 겹침을 허용하지 않되, 공통 f32 판정의 수 ULP 수준 접촉 오차는 유지한다.
공차는 들어갈 수 있는 접촉을 늘려 주지만, 탐욕적 후보 선택의 Order도 바꾸므로 최종 이용률이 항상 단조롭게 증가한다는 보장은 없다.

## 전처리와 시간

- 이산 회전은 입력에 선언한 것만 사용한다. 자유회전은 15도 간격 24개 제안으로 제한한다. 반전을 임의로 추가하지 않는다.
- 회전 도형은 먼저 준비한다. 쌍 NFP는 해당 부착 배치의 위치 평가 전에 준비하고, 방향을 포함한 정렬 배열에 캐시한다. 조회는 `binary_search`이며, 값 준비와 조회를 분리한다.
- 문서의 전체 쌍 선계산 대신 필요한 부착 배치만 준비한다. 매번 전역 합집합을 재구축하지 않는다.
- NFP 커널의 기존 0.001mm i64 그리드를 유지한다. 다른 엔진의 좌표 규약을 바꾸지 않는다.
- mm 모드를 끈 Draft NFP 제안에는 기존 `simplify_concave_only`를 0.005 면적 증가 비율로 사용한다. mm 모드를 켜면 인증된 import 도형을 그대로 NFP에 전달해 이 추가 면적 단순화를 생략한다. [mm 단순화](MM_SIMPLIFICATION.md)를 참고한다.
  충돌 인증은 단순화 제안 도형이 아닌 사용자가 설정한 `shape_cd`로 한다.
- 탐색 예산은 도형 준비부터 8초다. NFP 커널의 단일 호출 중단은 지원하지 않는다.
- 예산 소진 시 남은 조각을 현재 열 위쪽/새 열 아래쪽에 수직으로 쌓아 완료한다. 새 열의 완료 루트는 기존 원본 윤곽의 오른쪽 끝도 피한다. 수량을 누락한 부분 해를 성공으로 반환하지 않는다.
- 완료 배치와 최종 인증 시간은 예산 이후에도 필요하다. **8초 제한이 총 Init 8초 또는 10초 보장은 아니다.**
- `budget_exhausted`, `completion`, NFP 실패 수를 기록한다. 시간 소진 결과를 정상 접촉 탐색 결과와 구분한다.

## Order 차이 진단 (2026-09-07)

사용자가 지적한 대로 구현의 Order는 참조에서 유추되는 Order와 다르다.
수정 전 실제 첫 배치는 `35 → 32 → 34`였다. 참조의 좌하단은 ID 44이며,
참조 왼쪽 경계의 아래→위 배열은 `44 → 15 → 127 → 111 → 51 → 124`다.
이 배열을 실제 실행 이력으로 확정하지는 않는다.

`build_column_draft_with_order`는 원인 분리를 위한 진단 API다. `(item_id, copy_index)`의 완전한 순열만 받으며 위치/회전을 받지 않는다.
strict=false는 후보 우선순위만 바꾸고, strict=true는 틈 채움 및 시간 소진 완료에서도 지정 순서를 보존한다.
WPF 기본 생성기에서는 이 API를 사용하지 않는다.

참조 bbox xmin 오름차순, ymin 오름차순으로 만든 **유추 Order**를 사용했다.
입력 힌트를 제거하고 원본 기하 설정을 통일했으며, 시간 소진에 따른 완료 배치 효과를 제외하기 위해 세 실험 모두 예산 60초를 부여했다.
모두 예산 소진 없이 완료하고 기존 전체 수량/충돌 인증을 통과했다.

| Order 처리 | 길이(mm) | 이용률 | 열 수 | 코어 시간 |
|---|---:|---:|---:|---:|
| 기존 자동 | 7803.917 | 65.1850% | 14 | 5.001s |
| 참조 유추 순서를 후보 우선순위로 사용 | 8029.173 | 63.3563% | 16 | 4.812s |
| 참조 유추 순서를 엄격히 고정 | 12904.707 | 39.4196% | 29 | 0.787s |

이 수치는 원래 실행 순서를 찾았다는 증거나 Order가 중요하지 않다는 증거가 아니다.
현재 위치 선택/열 경계 규칙 아래에서 단순 좌표 정렬 순서만 주입하면 참조가 재현되지 않는다는 진단이다.

별도로 확인된 구조적 차이: 참조의 ID 44는 x=0, bbox 폭 586.325mm지만, 같은 왼쪽 경계에 ID 51(폭 605.175mm)이 있다.
수정 전 생성기는 루트가 정한 오른쪽 경계로 다음 조각의 bbox를 제한하므로 ID 44로 시작해도 ID 51을 그 열에서 거절했다.
참조의 ID 99도 x=125.85에서 x=729.45까지 뻗어 루트 44의 오른쪽 끝을 넘는다.
후속 수정에서 Order, 루트 폭 제한, 위치 점수, 부착 후보 범위를 함께 변경했다. 위 표는 원인 분리를 위한 **수정 전** 기록이다. 자동 Order는 여전히 원 엔진의 알려지지 않은 실행 순서를 재현한다고 주장하지 않는다.
