## 비교 방법

중간 실험은 양쪽 모두 Release, CGU=1, fat LTO, static CRT, 동일 기능으로 빌드한다. 비-PGO 실험과 기존 PGO DLL을 비교해 알고리즘 효과라고 주장하지 않는다. 최종 채택할 변경은 새 PGO로 다시 비교한다.

`scripts/explore_bench/paired.py`는 WSjk와 OPS2를 각각 seed 41/42/43, Explore 20초, 워커 3개, 겹침 2.2mm, PolySimpl 0.01로 실행한다. 각 쌍의 Init 좌표와 폭이 같아야 한다. A/B와 B/A 실행 순서를 교대하고 측정 중 다른 빌드나 벤치마크를 실행하지 않는다. Init 시간과 Explore 시간을 분리한다.

각 실행에서 실제 로드 DLL 해시와 ABI, 조각 수, 좌표 유한성, native 충돌 상태, 인증 콜백의 길이 비증가, 최종 결과가 더 좋은 콜백을 잃지 않았는지 검사한다. 겹침 판정 허용치를 바꾸지 않으며, 길이 비교 오차는 f32 직렬화 수준만 허용한다. 콜백 제한 때문에 목표 길이 도달 시각은 첫 관측 시각이며 실제 도달 시각의 상한이다.

유한한 마커·seed 실험으로 모든 입력에서 성능이 좋아짐을 보증할 수는 없다. 반복되는 퇴행은 채택하지 않고 해당 소스와 결과를 실험 폴더에 보관한다.

## 1. 충돌 수집기 희소 초기화

기존에는 후보마다 SecondaryMap 전체 슬롯을 초기화했다. 사용한 hazard 키만 별도 재사용 버퍼에 기록해 지우는 방식으로 변경했다. 충돌 탐색 순서, loss 합산 순서와 종료 조건은 그대로다.

희소 슬롯·키 세대 재사용 단위 테스트 및 후보 평가 차등 테스트가 통과했다. 독립 소스 검토에서 추가 정확성 문제는 발견되지 않았다. 추가 push/키 제거 비용이 발생하므로 마커 비교로 판단한다.

중간 비교: WSjk seed 41/42/43의 길이 차이는 -25.1392 / +37.2978 / -37.7660mm, OPS2 세 seed는 모두 0mm였다. 손해가 나온 WSjk seed42를 재측정한 20초와 60초에서는 모두 길이가 같았다. 최초 20초 결과와 재측정 결과 자체도 달라서 시간에 따른 탐색 선택 변동을 확인했다.

판정: 최종 PGO 확대·재측정 결과를 보고 **유지·배포**했다. 상세 데이터는 `p1-paired`, `p1-replay`에 있다. 코어 테스트는 754 통과, 13 ignored였다.

## 2. 동일 후보 재사용

먼저 `explore_candidate_probe`에서 고정 레이아웃·조각·가중치 검색 안의 좌표/각도 비트 중복을 측정한다. 매번 실제 평가를 실행하며, 최근 8회 중 재사용 가능한 결과의 예측과 실제 결과도 대조한다. Invalid는 정확한 loss가 아니라 기존 bound 초과라는 증거이므로 더 느슨한 bound에 재사용할 수 없다.

WSjk는 144개 검색에서 25,998회, OPS2는 111개 검색에서 19,022회 평가했다. 두 마커 모두 검색 안의 정확한 후보 중복은 0회였다. 축소 비율 0.995/0.99/0.98와 seed41/42/43의 고정 상태를 사용했으며 이동을 채택하며 계속 진행하는 전체 Explore 계측은 아니다.

판정: 캐시를 생산 경로에 추가하지 않음. 이 표본에서 얻을 재사용 이득이 없으므로 조회·키 준비 비용을 도입할 근거가 없다. 계측 예제와 `p2-probe-wsjk.json`, `p2-probe-ops2.json`을 남겼다. 일반적인 Invalid bound 규칙을 설명한 것이 실제 캐시가 검증됐다는 의미는 아니다(재사용 관측 자체가 0회).

## 3. 충돌 관계 갱신

조각 이동 후 기존 충돌을 지울 때 활성 이웃만 방문하는 방식을 시험한다. 조밀 행렬과 기존 합산 순서는 유지하고, 직접 행렬 수정·복사·복구 경로도 포함해 검증한다. 이웃 관리와 스냅샷 복사 비용까지 비교한다.

활성 이웃 목록은 스냅샷 간 공유하고, 실제 변경 때 복사한다. 공개 행렬 수정 API는 목록을 무효화하며 다음 이동에서 다시 만든다. 실제 이동, 키 세대 변경, COW, 가중치, 복구, 직접 손실 수정, 잠금 예외 테스트 6개가 통과했다.

WSjk seed41/42/43은 +49.2812 / +36.3740 / 0mm, OPS2는 모두 0mm였다. WSjk seed41 재측정도 +37.2397mm였다. 독립 코드 검토에서 정확성 문제는 발견되지 않았지만, 활성 이웃의 추가 COW/관리 비용을 포함한 전체 실행은 채택 기준을 만족하지 못했다. 이 원인별 CPU 비용을 별도로 분해 측정한 것은 아니다.

판정: **생산 코드 원복**. `tracker.rs`를 작업 전 사본으로 복구했다. 구현/테스트/DLL은 `p3`, 상세 결과는 `p3-paired`, `p3-replay`에 보관한다.

## 4. 실패 후보 풀 중복 제거

실패 경계에서 폭과 조각 ID/좌표/회전 비트의 multiset이 정확히 같은 후보만 합친다. 반복 ID의 개수는 보존하고 키 세대만 무시한다. 최대 32개 및 최소 loss 보존이 기준이다. 선택 확률이 달라지는 알고리즘 변경이므로 실제 길이를 별도로 비교한다.

테스트 7개와 독립 검토를 통과했다. WSjk seed41에서 +61.7568mm, 나머지 WSjk 두 seed와 OPS2 세 seed는 0mm였다. WSjk seed41 재측정은 +24.7641mm였다. WSjk의 이 20초 실행에서는 실패 보고가 종료 시 한 번뿐이어서 풀 다양성의 이득을 입증한 실험은 아니다. 전체 빌드의 실행 성능이 채택 기준을 만족하지 못한 것으로 판정하며, 이 수치만으로 중복 제거 자체가 원인이라고 단정하지 않는다.

판정: **생산 코드 원복**. `explore_mods.rs`, `optimizer/mod.rs` 복구 및 새 helper 두 파일 제거. 소스·테스트·DLL은 `p4`, 결과는 `p4-paired`, `p4-replay`에 보관한다.

## 5. 정체 시 제한된 공동 분리

두 충돌 유닛의 평행 이동 조합을 제한적으로 평가하는 초안이다. 별도 문제·트래커 사본에서 모든 외부 이웃을 검사하고, 그룹·잠금·회전·길이를 유지한다. loss 0이면 기존 정밀 인증을 거쳐야 한다. 중지/거절 시 실제 상태를 바꾸지 않는다. 복사 비용과 탐색 경로 변경으로 손해가 날 수 있어 단독 실험 후 결정한다.

Explore의 정체 경계에서 분리 호출당 최대 1회, 두 유닛의 최대 48개 이동 조합을 시험하도록 구현했다. Compress의 기존 분리 경로에는 추가하지 않았다. 단일 이동 테스트는 이산 후보 집합에 대한 것이며 기존 연속 탐색기로 절대 해결할 수 없다는 증명은 아니다.

집중 테스트 7개와 독립 코드 검토를 통과했다. 원본 한도 위반의 별도 거부 사례, 외부 이웃, 그룹, 잠금 예외, 관측된 모든 협조적 취소 지점의 상태 보존을 검사했다. 인증 함수 내부의 중지 지연까지 이 단위 테스트가 보장하지는 않는다.

20초 비교에서는 WSjk seed41/42/43이 0 / 0 / -12.4003mm, OPS2는 모두 0mm였다. 새 seed73의 60초 비교에서는 WSjk +12.1723mm, OPS2 0mm였다. WSjk 60초 재측정은 0mm로 길이 손해가 재현되지는 않았다. 그러나 같은 목표의 관측 시각은 WSjk 재측정에서 56.951→57.739초, OPS2 60초에서 39.708→40.078초로 늦었고, 일관된 이득을 입증하지 못했다.

판정: **이번 배포에서 제외하고 생산 코드 원복**. 기능/안전성 테스트 성공과 성능 채택을 구분했다. `separator.rs`를 복구하고 새 모듈·테스트를 제거했다. 소스·DLL은 `p5`, 결과는 `p5-paired`, `p5-long`, `p5-replay`에 보관한다. 재측정에서 반복적인 길이 퇴행을 입증했다고 해석하면 안 된다.

`retained-solver.patch`는 이번 채택 변경 두 파일만 되돌리는 패치이며 현재 소스에서 역적용 가능 여부를 확인했다. 작업 전의 다른 미커밋 변경까지 지우는 `git reset`을 사용하지 않았다. 이후 소스를 더 수정했다면 역적용 가능 여부부터 다시 확인해야 한다.

재현 도구는 `scripts/explore_bench/README.md`의 설명을 따른다. 기본 명령은 `paired.py --baseline <기존DLL> --candidate <비교DLL> --seeds 41 42 43 --seconds 20`이다. OPS2 입력이 target 정리로 없어졌다면 보관 폴더의 입력을 `--marker`로 지정한다.
