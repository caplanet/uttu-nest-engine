# 겹침 프록시의 `pd <= 0` 클램프 제거 — 실측 (2026-09-30)

## 무엇을 바꿨나

`swarm-core/src/quantify/overlap_proxy.rs` 의 `pole_overlap_decay` 와
`quantify/simd/overlap_proxy_simd.rs` 의 SIMD 커널(청크 루프 + 나머지 루프)에서
**폴이 겹치지 않으면(`pd <= 0`) 기여를 0 으로 자르던 분기**를 없앴다. 2개 파일, 분기 3곳.
설정·ABI·다른 알고리즘은 바뀌지 않았다.

```rust
// 전:  pd <= 0 → 0,  0 < pd < ε → ε²/(2ε − pd),  pd ≥ ε → pd
// 후:               pd < ε     → ε²/(2ε − pd),  pd ≥ ε → pd
```

수정 후 정의는 상류 swarm(`src/quantify/overlap_proxy.rs`) 및 논문
(arXiv 2509.13329, Algorithm 3)과 같다. 논문은 이 감쇠의 목적을 «폴이 겹치지 않는
충돌도 정량화에 기여하고 어디서나 매끄러운 기울기가 있게 하는 것» 으로 설명한다.
`docs/HANDOFF_SESSION.md` 의 «`pd <= 0` 클램프 — 우리가 고친 상류 버그» 서술은 틀렸다.

## 왜 문제였나

얕은 충돌(변끼리만 살짝 교차)은 폴이 겹치지 않는 경우가 대부분이다. 클램프가 있으면
그 쌍의 손실이 `ε × penalty` **상수**가 된다. 조각을 어느 방향으로 옮겨도 값이 같으므로
좌표 하강이 방향을 잡지 못하고, 충돌이 통째로 사라지는 자리를 우연히 뽑을 때까지
기다리게 된다. 기존 문서의 관측 — «겹침의 95.8% 를 풀고 마지막 4% 에서 멈춘다»,
«벽 근처 분리 한 번이 37~89초» — 과 맞는 기제다.

## 주의

* **손실 절대값의 스케일이 달라진다.** 얕은 충돌 쌍의 손실이 상수 `ε × penalty` 에서
  먼 폴까지 합산한 값으로 커진다. 이전 문서의 loss 수치(`min loss 2.92K` 등)나 loss 배율
  기준 노브(`max_loss_growth` 등)와 직접 비교하지 말 것.
* **이전 문서의 «기각» 판정은 전부 클램프가 있는 상태에서 잰 것이다.** «탐색 튜닝으로는
  못 올린다», «약 6390mm 고정점», «처리량은 레버가 아니다» 같은 결론은 수정 후 다시
  재기 전에는 근거로 쓰지 말 것.
* 상용 82.28%(겹침 조건 미상)까지는 아직 남는다. 이 수정은 격차의 일부를 닫는다.
