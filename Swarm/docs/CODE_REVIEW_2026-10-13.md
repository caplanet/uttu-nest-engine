# Rust 전체 점검 · 수정 내역 — 2026-10-13

브랜치 `v1_0_1_7` (기준 커밋 `8ce8874`, 브랜치 `v1_0_1_6`). 모든 커밋은 푸시했다.

사용자 지시: 모든 Rust 코드를 점검해 버그·성능·CPU·알고리즘 문제를 고칠 것. Sparrow 를 Swarm 으로
바꿀 것. 새 브랜치에 이슈 단위로 커밋·푸시할 것. 퇴근 뒤에는 묻지 말고 판단해서 처리하고 내역을 남길 것.
이 문서가 그 내역이다.

## 0. 먼저 알아 둘 것

- **Polish 의 끝나는 방식이 바뀌었다.** 고정점을 증명하면 예산을 기다리지 않고 바로 끝난다.
  남은 시간은 Reclaim(기본 켬)이 쓴다. 예전에는 마감까지 대기해서 Reclaim 이 항상 만료된 마감을
  받았다 — 기본으로 켜진 기능이 사실상 죽어 있었다. 단계별 소요 시간이 예전과 다르게 보일 수 있다.
- **이동 가능한 힌트가 원단 가장자리에 붙어 있어도 이제 버려지지 않는다.** 예전에는 단순화로
  부풀려진 충돌 도형이 경계를 미세하게 넘는 조각 하나 때문에 힌트 전체를 버리고 LBF 로 다시 지었다
  (`data/input/wsjk156.warmstart.json` 의 배치 156개가 전부 버려지던 것을 확인). 대신 Init 이
  분리 단계를 거치므로 그런 입력에서는 더 오래 걸린다(§5).
- **로컬 `Cargo.lock` 을 새로 맞췄다.** `Cargo.lock` 은 저장소에 없다(.gitignore). 새로 받은
  체크아웃이 얻는 버전과 같게 했다. (처음에는 그룹 분리 테스트 실패의 원인으로 봤으나 실제 원인은
  §3-10 의 그룹 자세 문제였다.)
- **테스트 프로필은 `debug-assertions = true` 다.** jagua-rs 는 이 설정에서 조각을 놓을 때마다
  쿼드트리를 통째로 다시 만들어 비교하고, 분리기는 매 이동마다 추적기를 재검증한다. 벽시계 예산을
  쓰는 코드(지역 보정 100 ms 등)는 테스트 프로필에서만 시간 초과가 난다. 이번에 그런 테스트들을
  고쳤다(§3).

## 1. 진행 방식

1. 빌드부터 살렸다. 워크스페이스 전체 `cargo check --all-targets` 가 실패하고 있었다(§2 의 첫 커밋).
2. 전체 Rust 코드(약 15만 줄)를 17개 영역으로 나눠 영역마다 리뷰 에이전트가 끝까지 읽었다.
   각 지적은 호출 경로를 따라가 검증한 것만 남겼다.
3. 영역별 적용 에이전트가 수정을 넣고, 이 세션에서 빌드·clippy·테스트로 검증했다.
4. 테스트 실패는 수정 전 커밋(별도 작업 트리)에서 같은 테스트를 돌려 "원래 있던 실패" 와
   "이번 수정이 만든 실패" 를 가렸다.

## 3. 판단한 사항과 근거

질문 없이 처리하라는 지시에 따라 아래는 내가 결정했다. 되돌리려면 해당 커밋만 revert 하면 된다.

1. **Polish 를 고정점에서 끝내기 (`a06a413`).** FFI 코드의 주석("폴리시가 일찍 수렴하면 이 시각까지가
   회수 루프의 예산이다")과 Reclaim 의 설계가 모두 이 동작을 전제로 한다. 반대로 마감까지 대기하는
   동작은 `8ce8874` 에서 들어왔고 테스트 4개(`postprocess_phases.rs` 3개, `disabled_work.rs` 1개)가
   그것을 단언하고 있었다. 설계 의도 쪽을 택하고 테스트를 고쳤다.
2. **크기 구역 레인의 NFP 기능 비활성화는 되돌렸다.** 리뷰는 레인이 구간마다 NFP 라이브러리를
   다시 만드는 비용 때문에 이를 끄자고 했다. 하지만 `issue6_grouped_real_ordering_dispatch_exits_for_single_item`
   이 크기 구역에서도 순서 탐색이 동작해야 한다고 명시한다. 계약을 따랐고, 근본 해결(레인별 라이브러리
   유지)은 §6 에 남겼다.
3. **SIMD 커널 선택 변경은 한 번 되돌렸다가 다시 넣었다.** 1 ULP 차이 테스트 실패의 원인으로 의심했으나,
   실제 원인은 테스트 쪽(쌍 손실의 피연산자 순서)이었다.
4. **지역 보정의 시간 예산.** 릴리스 100 ms 는 그대로 두고, `debug_assertions` 빌드에서만 5초로 했다.
   배포 DLL 동작은 바뀌지 않는다.
5. **가장자리 힌트 밀어 넣기의 상한 2 mm.** 원래 외곽이 원단 안에 있고 충돌 도형만 넘친 경우로 한정했다.
   2 mm 는 단순화 부풀림과 일반적인 조각 간격을 덮는 값이다. 그보다 크게 넘치면 예전처럼 거부한다.
6. **수정 전부터 실패하던 테스트 (`ecbf64c`).**
   - `issue4_cache_rejects_exact_frozen_drift…`: 고정 조각을 원단 왼쪽 바깥(x = −10)에 두어 jagua-rs
     디버그 검사에 걸렸다. 같은 조건(같은 폭, 더 압축된 자세)을 만족하는 원단 안 위치로 옮겼다.
   - `harness_metadata_and_treatment_snapshots_are_stable`: `native_bundle` 은 기본 설정을 뜻하는데
     테스트가 예전 기본값(스왑·R&R·홀 채우기 켬)을 고정값으로 단언했다. 현재 기본값과 비교하게 했다.
   - `tracker_prepared_losses_match_reference…`: 추적기는 쌍마다 한 값만 저장하고, 겹침 근사는
     피연산자 순서에 따라 마지막 비트가 달라진다. 두 순서 중 하나와 일치하면 통과로 했다.
   - `issue7_split_scores_each_proposal_once…`: 800조각 픽스처가 디버그 검사 때문에 수 분 걸린다
     (릴리스 0.5초). 디버그 빌드에서만 800 경우를 뺐다.
   - `issue10_warm_micro_overlap_*`, `slightly_overlapping_hints_are_repaired_not_discarded`:
     4번 항목으로 해결.
7. **압축 감쇠 시작 시각 변경은 되돌렸다 (`dd09bfa`).** 리뷰는 감쇠를 "마감 − 압축 시간 한도" 에서
   시작해 준비 시간을 보정하자고 했다. 하지만 그룹 엔진은 압축을 짧은 구간 마감으로 반복해 부르므로
   감쇠가 처음부터 끝 값 근처에서 시작한다. 실제로 `disabling_local_polish_does_not_disable_reclaim`
   이 기본 설정에서 5번 중 4번 실패했고, 되돌리자 5번 모두 통과했다. 이득(준비 시간 보정)이 작아 되돌렸다.
8. **래스터 FFI 테스트**는 래스터 LBF 후보가 `capmods` 기능에만 있으므로 그 기능에 한정했다
   (테스트 파일 머리말도 그 기능으로 실행하라고 적고 있었다. 수정 전에도 기본 설정에서 실패했다).
9. **이전 세션 종료.** 10-13 저녁 마지막 전체 테스트 도중 세션이 끝나 결과가 남지 않았다. 10-14 에
   다시 돌렸고, 그 과정에서 아래 10 ~ 12 를 찾았다.
10. **그룹 자세 무효화 (`2ba6d36`).** 샘플러는 PlaceGroup 의 대표 조각만 원단 안에서 뽑는다. 대표를
    위쪽 가장자리에 붙이면 강체로 붙은 구성원이 원단 밖(높이 38 mm 원단에서 y 40 ~ 50)에 통째로 놓였고,
    그룹 전체 손실이 줄면 그 자세가 채택됐다. jagua-rs 는 쿼드트리 범위 밖 도형을 예상하지 않는다.
    `f98a0f8` 의 래스터 수정으로 LBF 가 위쪽 가장자리에 붙인 배치를 만들면서
    `grouped_separation_preserves_relative_pose_and_tracker` 가 매번 실패했다(`git bisect` 로 확인).
    구성원 하나라도 원단과 전혀 겹치지 않는 자세는 이제 무효다. 처음에 "Cargo.lock 차이" 로 판단했던
    것은 우연히 한 번 통과한 결과를 잘못 읽은 것이었다(§0 의 해당 문장은 사실이지만 원인은 아니었다).
11. **폭 완화 롤백 전 폭 재설정 복원 (`e12d763`).** 리뷰는 이 호출을 불필요하다고 지웠다. 롤백이 폭도
    복원하는 것은 맞지만, 폭 변경은 작업자 재동기화(RNG 재설정 포함)도 한다. 지우자
    `unresolvable_relief_still_terminates_on_consecutive_failures` 가 6번 중 1번 60초 제한까지 돌았다
    (수정 전 0/5, 복원 뒤 0/8).
12. **Reclaim 테스트 예산 (`17ec463`).** `disabling_local_polish_does_not_disable_reclaim` 은 0.1초 안에
    Reclaim 한 주기가 끝나야 했고, 전체 실행의 부하에서 가끔 실패했다. Reclaim 은 이미 한 주기로 묶여
    있으므로 예산을 1초로 늘려도 테스트 의미는 같다.
13. **부하에 민감한 테스트는 그대로 두었다.** 그룹 엔진의
    `structure_p1_uses_one_deadline_and_round_robins_construction_starts`(P1 이 400 ms 안에 끝나야 함)와
    `group_worker_cap_wires_both_pools_and_gives_each_p4_lane_one_cycle`(P4 400 ms 안에 레인마다 한 주기)은
    따로 돌리면 5/5 통과하지만 전체 실행의 부하에서 가끔 실패했다. 시간 상한 자체가 검사 대상이라
    늘리면 검출력이 떨어진다.
14. **적용하지 않은 리뷰 지적.** 효과가 불분명하거나 변경이 큰 것은 넣지 않았다:
   reflow 규칙 변경(재측정 필요), tail_reflow 비용 계수(설계 문제), 래스터 스캔라인 채우기,
   프로필 평가기의 교차 계산 재구성, 슬라이드 클로저 호이스팅, LP 모서리 사전 계산, global_candidates
   메모화, 조기 보고의 결정성(제품 판단), 그룹 레인 Init 병렬화(취소 토큰 전파가 필요).

## 5. Init 시간 분석 (질문: JSON 대신 메모리 참조로 넘기면 빠른가?)

결론: **빨라지지 않는다.** `tests/init_timing_probe.rs` 로 wsjk156(156조각, 조각당 꼭짓점 약 215개,
JSON 약 3 MB)을 릴리스 빌드로 쟀다.

| 단계 / 경우 | 시간 |
|---|---|
| JSON 파싱 | 15 ~ 25 ms |
| V2 JSON 파싱 + 검증 (`placed_hint` 156개) | 약 25 ms |
| 형상 준비 (다각형 단순화, 충돌 구조) | 약 230 ms |
| Init, 힌트 없음 (LBF) | 0.5 ~ 0.7 s |
| Init, 힌트 없음, NFP-LBF 시드 켬 (WPF 기본) | 약 16 s |
| Init, 이동 가능 힌트 156개 (가장자리 수정 뒤) | 1.0 ~ 1.6 s |
| Init, 고정 힌트 156개 | 0.3 ~ 0.45 s |
| 메모리 힌트 배열 vs V2 JSON | 차이 없음 (오차 범위) |

- JSON 처리는 Init 의 수 %다. 메모리 힌트 배열이 JSON 보다 빠르지 않았다.
- **배치 조각이 많을수록 Init 이 길어지는 실제 원인**은 시드 분리다. 맞닿은 조각들은 단순화로 부풀린
  충돌 도형 기준으로는 서로 겹친다(진입 손실 약 230만). 지역 보정(이동 0.25 mm 이내)으로는 풀리지 않아
  전체 분리 단계가 0.6 ~ 1.2초를 쓴다. 조각 수가 늘수록 이 시간이 는다.
- **NFP-LBF 시드(WPF 기본 켬)는 힌트가 없을 때 Init 을 약 16초로 만든다.** 순서 탐색 예산 10초, NFP
  캐시 준비, 시드 대결(짧은 탐색 2회, 조각당 15 ms·최대 3초)이 더해진다. 힌트가 있으면 이 단계는 건너뛴다.

줄이는 방법(코드 변경 없이): 고정해도 되는 조각은 `is_freeze` 로 넘긴다(분리를 건너뜀). 힌트를 정확히
지키고 싶으면 PolySimpl 을 끄면 부풀림이 사라진다. 힌트 없는 실행에서 Init 이 길면 NFP-LBF 의
`total_budget_ms` 를 줄인다.

## 6. 남은 과제

- **R&R 와 홀 채우기는 빈 구현이다** (`optimizer/lns.rs`, `optimizer/polish/holes.rs`). 탈출의 Hard
  단계, 충돌 폭발 3단계, Structure P3/P4 의 루인, Init 홀 채우기가 모두 아무 일도 하지 않는다.
  Hard 탈출은 이번에 Medium 으로 대체했다.
- **ABI 예약 필드** `portfolio_k`, `probe_budget_ms`, `rnr_original_candidate` 는 코어가 쓰지 않는다.
  헤더와 C# 주석에 예약으로 표시했다.
- **크기 구역 그룹 레인**이 구간마다 Separator 와 NFP 라이브러리를 다시 만든다. NFP 기능을 켜면 구간이
  준비에 소진된다. 레인별로 라이브러리를 유지하도록 고쳐야 한다.
- **Xpress 상수**는 공개된 xprs.h 값으로 바꿨지만 실제 라이브러리로 확인하지 못했다(설치되지 않음).
- **swarm-nfp**: 맞닿은 구멍이 있는 영역은 이제 subtract/locate 에서 받아들이지만, `prepare`(전체
  삼각분할)는 Clipper 가 꼬집힌 경로를 내서 여전히 실패한다. 경로 분할이 필요하다.
- **refplace** 는 이제 각 조각의 첫 회전만 평가한다(다른 회전의 앵커는 맞지 않았다). 품질 A/B 를 재지 않았다.
- **nesting-engine `--best`** 수치는 여유 상자 색인 수정으로 바뀐다. wsjk156 재측정이 필요하다.
- **JNI**: `isStopRequested`/`stopAndWait` 는 Java 가 받을 수 없는 핸들을 받는다(사용 불가 API).
  `get_string` 은 CESU-8 이라 BMP 밖 문자가 든 경로를 거부한다.
- **wasm** 빌드에는 `--cfg getrandom_backend="wasm_js"` 가 필요하다(`.cargo/config.toml` 에 없음).
- 시드 분리(§5)를 근본적으로 줄이려면 힌트 배치를 원래 외곽 기준으로 인증하는 경로가 필요하다.
