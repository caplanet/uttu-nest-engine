# Explore 정체 분리 개선 — 2026-09-10

세 알고리즘을 Config 및 WPF에 연결했다. 사용자 요청에 따라 최종 배포에서는 PGO를 제외하고 일반 Release를 사용한다. 아래에서 기능 검증과 성능 검증을 구분한다.

## 백업과 범위

`backups/separator-repair-20260910-171758`에 작업 시작 당시 소스 458개, 기존 미커밋 diff, DLL/PDB를 보관했다. ZIP SHA256은 `78ADDBC3BCC56A4208E97F69CF09D40A549E723C9891B8591D5F0B5AD600C941`이며 ZIP 무결성을 확인했다. 이전 작업의 백업도 그대로 보존한다.

작업은 AdaptiveAlgorithm2에서만 진행했다. Uttu.Nest/fable 소스는 읽거나 변경하지 않았다. 기존 shrink 정책, 동기식 워커 선택, 원본 겹침 한도, 잠금 예외, 그룹과 허용 회전 규칙을 바꾸지 않았다.

## 사용 방법

WPF 설정의 Explore 구역에 `Explore stagnation repair (opt-in)`을 추가했다.

| UI | 기능/의미 | 기본값 |
|---|---|---|
| Contact direction | 실제 정점·변 접촉에서 이동 후보 생성 | 꺼짐 |
| Cluster LP | 작은 주변 집단의 이동량을 선형계획으로 계산 | 꺼짐 |
| Blocker chain | 새 충돌을 만드는 이웃을 따라 연쇄 이동 | 꺼짐 |
| Stagnation | 의미 있는 loss 감소가 없었던 반복 수 | 24 |
| Passes | 분리 호출 한 번당 최대 repair 횟수 | 2 |
| Units | LP/연쇄 이동에 참여하는 최대 이동 단위 수 | 4 |
| Evaluations | repair 한 번의 전체 배치 후보 평가 상한 | 64 |
| Budget (ms) | repair 한 번의 협조적 시간 예산 | 20ms |
| Move (mm) | 조각/그룹의 시작 위치 대비 이동 거리 한도 | 2mm |

`Move (mm)`는 겹침 허용값이 아니다. `piece_overlap_mm`은 기존처럼 별도로 적용된다. 그룹 전체를 하나의 이동 단위로 취급하며 회전은 바꾸지 않는다.

Rust 설정은 `ExplorationConfig.repair`, 관리 코드 설정은 `Exploration.Repair`, C 설정은 `CSwarmConfig.repair`이다. 비정상 입력은 유한한 안전 범위로 제한한다. 모두 꺼져 있으면 repair의 그룹 목록·형상 후보·LP 모델·사본을 준비하지 않는다.

Basic/Adaptive Explore, Escape Explore, Structure의 P3 Explore와 P4 재분리에 적용한다. NFP 순서 탐색은 Separator를 직접 사용하지 않으며, 해당 탐색이 기존 Explore로 돌아오는 경로에는 설정을 전달한다. Init/Compress/Polish의 분리 호출은 이 Explore 설정으로 변경하지 않는다.

## 실행 방법

현재까지 가장 낮았던 비가중 loss보다 0.5% 이상 낮아지는 개선이 없었던 반복이 누적되면 repair를 시도한다. 시간 경과나 `min_l` 절대값을 기준으로 켜는 기능은 아니다. 이 카운터는 기존 Separator 종료 기준과 별도이며 기존 종료/shrink 정책을 대체하지 않는다.

동시에 켜면 Contact direction → Cluster LP → Blocker chain 순서로 시도한다. 앞선 방법이 개선에 성공하면 해당 pass를 끝낸다. 시간·전체 후보 예산을 공유하므로 한 pass에서 세 방법이 모두 실행된다는 보장은 없다. LP의 형상/모델 상한 초과는 LP만 포기하며, 남은 예산이 있으면 연쇄 이동으로 이어진다.

### 접촉 방향

양쪽 도형의 정점과 변을 제한적으로 표본 추출해 수직 투영 및 끝점 접촉 후보를 만든다. 접촉점, 작은 초과 이동, 부분 이동 등을 기존 평가기로 확인한다. 실제 충돌하는 이웃을 우선하며, 원단 경계 후보도 포함한다.

한 형상 쌍에서 최대 2,048회 투영, 32개 이벤트/후보로 제한한다. 비볼록 형상의 모든 탈출 방향을 열거하는 정확한 NFP 탐색은 아니다. 후보 기하가 부정확하거나 불완전하더라도 기존 평가와 최종 인증을 우회할 수 없다.

### 작은 집단 LP

가까운 이동 단위들을 골라 접촉 방향의 분리 조건, 이동 한도, 남은 침투를 나타내는 slack과 작은 이동 비용을 선형계획으로 푼다. 기존 pure Rust Microlp 백엔드를 사용하며 외부 솔버 DLL은 필요 없다.

변의 법선과 투영 구간을 사용하므로 비볼록 도형은 보수적인 볼록 외곽 근사로 취급될 수 있다. 모델이 불가능하거나 도움이 안 되는 방향을 제안할 수 있어, 실제 형상/모든 이웃 평가가 채택을 결정한다. strip을 줄이는 Polish LP를 그대로 호출하는 방식은 아니다.

### 연쇄 이동

첫 조각의 제안 이동이 이전에 없던 이웃 충돌을 만들면, 해당 이웃의 접촉 후보를 계산해 연쇄적으로 움직인다. 기존에 충돌하지 않았던 조각도 탈출 공간을 막으면 대상이 된다. 이미 방문한 단위는 다시 확장하지 않으며 그룹/깊이/평가 예산으로 제한한다.

임시 충돌 증가는 사본에서만 존재한다. 중간 연쇄 상태는 콜백이나 현재 레이아웃에 반영하지 않는다.

## 채택과 중지

- 전체 가중 loss는 엄격히 감소하고, 비가중 loss는 증가하지 않아야 한다. 여기서 loss는 원본 침투 깊이 mm 자체가 아니다.
- 모든 이웃과 원단 경계는 기존 CollisionTracker로 다시 평가한다. 현재 strip 길이는 그대로 유지한다.
- loss가 0인 후보는 원본 형상·허용 회전·그룹·잠금 조건의 기존 정밀 인증도 통과해야 한다.
- 마지막 중지/시간 확인 후 사본을 한 번에 채택한다. 취소되거나 거부된 후보는 기존 상태를 변경하지 않는다.
- 시간 예산은 협조적 한도다. 단일 레이아웃 복사, 트래커 연산, 원본 정밀 인증 내부까지 강제로 선점하는 실시간 보장은 없다.

## ABI와 빌드

설정을 C 구조체 끝에 추가하면서 ABI를 15에서 16으로 올렸다. `CSwarmConfig`는 776에서 816바이트이며 새 블록 시작은 776이다. Rust, 관리 코드, C 헤더를 함께 갱신했다. 오래된 호스트는 새 DLL과 함께 사용하지 않아야 하며, 관리 코드의 ABI 검사가 불일치를 차단한다. Uttu.Nest 연동 파일은 이번 범위에서 수정하지 않았다.

## 검증 결과

최종 소스의 전체 코어 777개 통과(기존 제외 13개), 네이티브 105개 통과, 관리 코드 99개 통과, 통합 테스트 11개 통과. 합계 992개 통과이며, 집중 repair 23개 검사는 코어 수에 포함된다. 사선 접촉, 포함 도형 탈출, 음수 접촉 간격, 실제 충돌 감소, 연쇄 이웃 이동, 그룹, 잠금, 중지 복구 및 꺼짐 경로의 결과/난수 동일성을 검사했다.

WPF Release 빌드 성공. 기존 `MainWindowViewModel`의 nullable 경고와 `DockDocumentItemViewModel`의 Reactive 소스 생성 경고가 발생했으며 이번 변경 파일의 경고는 없었다. 실제 화면 조작 검증은 수행하지 않았다.

최종 Rust 빌드는 `opt-level=3`, `codegen-units=1`, `fat LTO`, `+crt-static`을 사용한다. `profile-generate`와 `profile-use`는 사용하지 않는다. PGO 제외 요청 전에 만들어진 실험 DLL 및 비교 자료는 이전 실험으로 구분하며 최종 WPF에 배포하지 않는다.

최종 일반 Release의 마커 비교·DLL 정보는 완료 후 이 문서에 기록한다.
