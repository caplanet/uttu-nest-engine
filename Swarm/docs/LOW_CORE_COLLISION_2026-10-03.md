# 충돌 해소 경로 단순화와 저코어 실행

R&R, 주기적 swap, hole fill, 접촉 방향 복구, cluster LP 복구, blocker chain과 이들을 선택하던 ALNS/portfolio 실행을 제거했다. 별도 initial/attach 엔진의 R&R·chain 구현도 삭제했다. 초기 배치와 기본 탐색의 교란, GLS 충돌 가중치, 정확 충돌 인증, 고정 조각 및 강체 그룹 보존은 유지한다. Polish의 LP 압축은 제거한 cluster LP 복구와 별개로 유지한다.

기존 C ABI 구조체의 크기와 필드 순서는 유지한다. 이전 설정의 제거된 옵션을 켜도 실행되지 않는다. Rust 공개 함수는 소스 호환용 무동작 진입점만 남겼다. 이전 Reclaim R&R 모드는 압축 재진입으로 처리한다. WPF에서는 해당 조작 항목을 제거했다.

WPF 초기값과 권장 설정은 겹침 허용 **0.08mm**, 원단 침투 **0.2mm**다. 같은 값으로 실제 FFI 탐색·압축을 검증했다.

## 실행 비용

- 1워커는 별도 Rayon 풀을 만들지 않고 호출 스레드에서 처리한다.
- 1워커는 현재 배치와 충돌 트래커의 소유권을 넘겨 라운드마다 배치 복원과 행렬 공유를 피한다.
- 64조각 이상 병렬 배치는 첫 워커에 현재 상태를 넘기고 나머지 워커만 스냅샷을 병렬 복원한다. 작은 병렬 배치는 추가 트래커 스냅샷 비용을 피하려고 기존 복원 경로를 유지한다.
- 승리 워커의 배치·트래커를 함께 넘긴다. 각 워커의 난수와 캐시는 계속 같은 워커에 남으며, 동률이면 이전과 같은 첫 워커를 선택한다.

## 라운드 벤치마크

`low_core_round_benchmark`는 변경 전 라운드 함수를 테스트 전용으로 보존해 비교한다. 입력당 시드 42/71/1234, 동일 초기 배치와 난수, 100라운드다. 충돌이 해소되면 폭을 추가로 줄여 충돌 해소 작업을 계속한다. import·초기 배치 시간과 제거된 보조 연산자의 비용은 제외한다. 출력 배치와 최종 충돌 손실이 두 경로에서 동일한지도 확인한다.

Release 최적화, LTO off, codegen units 16에서 측정한 세 시드의 시간 합계:

| 입력 | 워커 | 기존 시간(s) | 변경 시간(s) | 처리량 비율 |
|---|---:|---:|---:|---:|
| fu | 1 | 0.433114 | 0.387394 | 1.118 |
| fu | 2 | 0.383600 | 0.384233 | 0.998 |
| fu | 4 | 0.525017 | 0.522626 | 1.005 |
| wsjk156 | 1 | 4.364273 | 4.426589 | 0.986 |
| wsjk156 | 2 | 3.986823 | 3.993001 | 0.998 |
| wsjk156 | 4 | 3.983384 | 3.974821 | 1.002 |

1워커 소형 입력에서 처리량이 약 12% 늘었다. 다른 조합은 차이가 작거나 일부 느렸다. 이 측정으로 모든 입력의 속도 향상이나 전체 탐색 밀도 개선을 주장하지 않는다. 보조 연산자 제거로 줄어든 전체 비용은 이 표에 포함되지 않는다.

실행:

```powershell
$env:CARGO_PROFILE_RELEASE_LTO='off'
$env:CARGO_PROFILE_RELEASE_CODEGEN_UNITS='16'
cargo test --offline -p swarm-core --release --features 'capmods adaptive structure-first' --lib low_core_round_benchmark -- --ignored --nocapture --test-threads=1
```

## 회귀 검증

- 코어 단위 테스트 719개 통과, 기존 장시간/실험 테스트 22개 제외.
- 코어 통합 테스트 37개 통과: 고정 조각, 제거된 연산자 무동작, 병렬 처리, Polish, 정지 응답.
- 공개 FFI 테스트 11개 통과: 1·2·4워커와 두 시드에서 Explore/Compress 완료, 조각 수 유지, 폭 증가 없음, 충돌 상태 없음; disabled work, 단계 반복 호출, 고정 조각.
- C# 호스트 테스트 182개 통과.
- 동일 시드의 반복 라운드에서 배치·충돌 손실·워커 난수 일치 및 호출 스레드에서의 조기 콜백/정지 결과 보존을 검증했다.
- `simd,capmods,adaptive,structure-first,jni` 기능을 포함한 기본 Release(fat LTO) DLL 빌드 및 WPF Release 빌드 성공. WPF 출력의 DLL은 Cargo 출력과 동일하다.
- 빌드한 실제 DLL을 C#에서 로드해 ABI와 필수 export를 확인하고, 1·2·4워커에서 겹침 0.08mm·원단 침투 0.2mm로 Init→Explore→Compress를 추가 실행했다. 이전 R&R/swap/repair 플래그를 켠 상태에서도 세 실행 모두 조각 수·충돌·콜백·최종 해 검사를 통과했다. 진단 결과는 `target/low-core-smoke/`에 저장했다.

`disabled_work`의 이전 단계 순서 및 그룹 LP 비활성 가정은 현재 공개 API 계약과 달라 수정했다. 공개 단계는 초기 해에서 직접 실행하거나 반복 호출할 수 있고, 그룹 LP도 지원하므로 empty-phase 테스트는 모든 패스를 명시적으로 끈다. 충돌 인증 실패 테스트는 무제한 터미네이터 대신 유한 예산을 사용해 재시도 이후에도 유효하지 않은 결과가 공개되지 않음을 확인한다.
